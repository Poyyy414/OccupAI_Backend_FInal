# OccupAI Camera To Render Setup

## Why localhost works while Render says Waiting

The webcam and computer-vision detector run on the laptop. Render cannot see
the laptop camera, and `127.0.0.1` always means the current computer/server.
The detector must publish its CV state to the Render backend over HTTPS.

The backend already accepts authenticated detector updates at:

`POST /yolo/update`

## Configure the Render service

In Render → Environment, set a unique `CAM_TOKEN`. Keep this value private.
The local detector must use the exact same value.

## Configure the laptop detector

In the local, uncommitted `.env`, use the following values:

```text
DEPLOY_MODE=local
LOCAL_BACKEND_URL=http://127.0.0.1:8000
REMOTE_BACKEND_URL=https://occupai-backend-final-last.onrender.com
PUSH_LOCAL_BACKEND=true
PUSH_REMOTE_BACKEND=true
CAM_TOKEN=<the same unique CAM_TOKEN configured in Render>
```

Do not commit the real token. `REMOTE_BACKEND_URL` is optional; it was added so
the local and deployed destinations are not confused with one `BACKEND_URL`.

## Verify it

1. Start the local FastAPI backend if localhost is also needed.
2. Start both workers with `.\\start_two_cameras.ps1`.
3. At startup, confirm each worker prints both local and Render push targets.
4. Confirm the detector logs successful `/yolo/update` requests, not HTTP 401,
   403, timeout, or connection errors.
5. Open the Render dashboard and wait up to the camera-state timeout window.
   Overview should show detector live, occupied/free slots, and FPS.

If Render shows HTTP 401, the two `CAM_TOKEN` values do not match. If it shows
timeouts, check the laptop internet connection and Render URL. If only local
works, check `PUSH_REMOTE_BACKEND=true` and the printed target list.

## Two-camera local setup

The admin web Live Feed shows separate **Car Camera** and **Motorcycle Camera**
cards. Camera identity is strict: the launcher starts exactly one process for
each physical camera using these settings.

Motorcycle worker:

```text
CAMERA_ID=motorcycles
CAMERA_ROLE=motorcycle
WEBCAM_INDEX=1
STREAM_PORT=8002
```

Car worker:

```text
CAMERA_ID=cars
CAMERA_ROLE=car
WEBCAM_INDEX=0
STREAM_PORT=8001
```

Do not start a third or legacy `main` worker. The launcher prevents duplicate
launcher instances and fails if either required stream port is already in use.

Each worker loads its fixed normalized boxes from
`yolo_service/camera_layouts.json`: 10 car boxes and 20 motorcycle boxes. The
backend publishes a combined occupied/free percentage only while both workers
are fresh and reporting. Otherwise the combined occupancy is Unknown while
the official configured capacity remains 30.

## Online live video

The preferred online path is independent from YOLO processing:

```text
USB cameras -> YOLO workers -> annotated MJPEG -> FFmpeg (H.264)
                                                   |
                                                   v
                         MediaMTX (LL-HLS) -> Cloudflare Tunnel
                                                   |
                                                   +-> admin web, driver web, Flutter app
```

This keeps video playback moving even when a detector inference takes longer.
The detector continues sending occupancy data to Render separately.

Start MediaMTX and the two YOLO workers first. The workers own the USB cameras
and expose their latest annotated frames on ports 8001 and 8002. Then publish
those processed feeds from separate terminals:

```powershell
ffmpeg -fflags nobuffer -flags low_delay -i http://127.0.0.1:8001/stream -an -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -r 15 -g 15 -keyint_min 15 -sc_threshold 0 -bf 0 -f rtsp -rtsp_transport tcp rtsp://127.0.0.1:8554/cars
ffmpeg -fflags nobuffer -flags low_delay -i http://127.0.0.1:8002/stream -an -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -r 15 -g 15 -keyint_min 15 -sc_threshold 0 -bf 0 -f rtsp -rtsp_transport tcp rtsp://127.0.0.1:8554/motorcycles
```

This avoids opening each USB camera from both OpenCV and FFmpeg. It also means
the online feed contains the same parking boxes, detections, status colors, and
FPS display generated by the computer-vision workers.

Expose MediaMTX's HLS port over HTTPS:

```powershell
cloudflared tunnel --url http://127.0.0.1:8888
```

Copy the generated `https://...trycloudflare.com` address. In Render's
Environment page set this variable, without a trailing slash:

```text
MEDIA_STREAM_BASE_URL=https://your-current-tunnel.trycloudflare.com
```

Redeploy the backend after changing the value. The authenticated
`/api/media-config` endpoint then gives the web dashboards and Flutter app the
`cars` and `motorcycles` HLS addresses. The backend also adds only that HTTPS
origin to the dashboard frame security policy.

Keep MediaMTX, both FFmpeg publishers, Cloudflare Tunnel, both YOLO workers, and
the laptop internet connection running. A Quick Tunnel address changes whenever
it is restarted, so update `MEDIA_STREAM_BASE_URL` in Render each time. Use a
named Cloudflare Tunnel and owned hostname later if a permanent URL is needed.

### Fallback behavior

If `MEDIA_STREAM_BASE_URL` is not configured, OccupAI uses the existing
authenticated JPEG/MJPEG relay automatically. The detector
includes its latest annotated frame in `/yolo/update`; the backend serves it
through `/api/stream` and `/api/camera-frame`. This fallback is less smooth but
keeps camera monitoring available without exposing the laptop's local ports.
If a configured Quick Tunnel stops, restart it and update the Render variable;
the camera cards provide a retry control while the new stream starts.
